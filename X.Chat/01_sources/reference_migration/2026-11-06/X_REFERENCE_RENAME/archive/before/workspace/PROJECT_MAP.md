## TACC cluster-internal SSH: login3 access

Verified 2026-10-19 from LS6 compute node `c318-008`: use **`BatchMode=no`**
when connecting to login3 for read-only checks or an authorized Slurm submission:

```bash
ssh -T -o BatchMode=no -o ConnectTimeout=10 login3 'hostname' < /dev/null
```

`BatchMode=yes` accepted the SSH key but prevented the subsequent
keyboard-interactive authentication step from completing. With `BatchMode=no`,
the connection succeeded without a user-supplied password or token, despite
printing the standard TACC authentication banner. Closed stdin does not supply
credentials. If authentication fails, report the failure; this observation
does not establish token-free access from a Mac or outside TACC, or on other
clusters. This is an authentication option, not a sandbox/network permission
override; use required tool escalation when applicable.

Replace `'hostname'` only with the intended authorized command; connecting does
not authorize a job submission or execution of another repository's startup
workflow. Keep compute workloads on allocated compute nodes. See the
[archived connection investigation](_operations/reports/access/2026/10/19/2026-10-19_OPS-VSCODE-001_connection_closeout/README.md)
