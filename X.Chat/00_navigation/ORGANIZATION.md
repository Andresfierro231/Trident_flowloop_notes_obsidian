# Organization and maintenance rules

- Keep one authoring owner per kind of material; navigate with links rather than maintaining parallel copies.
- Existing top-level folders remain the subject record: overview, setup/geometry, model notes, meetings, research and appendix.
- `X.Chat/00_navigation/`: stable entry points and conventions.
- `X.Chat/01_sources/`: document register, machine-readable inventory and image/link routes; no replicated raw photo/data collection.
- `X.Chat/02_synthesis/`: maintained cross-source idea reconciliation; organize by research question/mechanism rather than by paper.
- `X.Chat/03_proposal/`: writing packages; dated packages carry status/base hashes and are not new proposal authorities.
- `X.Chat/04_decisions/`: append author answers verbatim, then distinguish interpretation and affected claims.
- `X.Chat/05_handoffs/`: dated changes, checks and next actions; one handoff per coherent task rather than many competing reports.
- `X.Chat/90_templates/`: reusable bullet structure; `tools/`: repeatable inventory/link checks.
- Use existing N01–N11/R01–R05 and literature S/claim IDs when referring to the same sources. MS01 adds the exact master’s repository without replacing LIT-003. New local IDs must not renumber established registries.
- Every consequential bullet should have: idea → evidence locator → implication/limit → next expansion task, where needed. A file’s presence is not proof it was read.
- Source order: current explicit author direction controls intent; source-qualified manuscript/data evidence controls scientific claims; dated meetings/plans supply context. A newer date alone does not qualify a geometry or model.
- Scientific statuses: proposed / implemented / numerically checked / calibrated / retrospectively assessed / independently assessed. Scope approval is separate from all of them.
- Store large run data and immutable bundles with their existing owners. Index run/configuration/version/commit/hash and result path; keep raw inputs unchanged.
- For every experiment preserve facility/revision, run ID/time window, units, channel meaning, boundary/initial information, calibration, exclusions and development/assessment role.
- Keep original photo embeds/page fragments and the parent note. Add caption-purpose, facility/revision and selection status; do not infer dimensions or construction authority from an uninspected image.
- New content goes into an existing maintained synthesis note whenever possible. Use dated evidence records for changed findings, and point to superseded versions instead of deleting history.
- Future physical reorganization requires a move map and inbound-link update/check. Current unresolved links are repair candidates, not evidence that a source never existed.
- At each writing milestone: reconcile source/decision changes, refresh inventory, check links, update the proposal bullets and record one handoff. No recurring automation is scheduled.

- `X.Chat/06_hpc_exchange/`: Box-mediated local/HPC questions, dated outgoing requests, untouched incoming responses and subsequent reconciliations; no implicit delivery or live-agent status.
- Proposal and research questions organize the work; the literature review supplies sources and existing answers. Use the report catalog for code/results context and the planning-coverage table for historical TODO disposition.
